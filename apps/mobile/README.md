# Tazumo mobile (Expo)

Expo SDK 53 / React Native 0.79 app for iOS and Android. App ID on both platforms: `io.wopee.demos.tazumo`. Synthetic catalogue and in-memory cart only: checkout is disabled, and there are no payments, merchants, couriers or ETAs.

## Screens and test identifiers

Catalogue (search, categories, inline mini-cart) -> product detail -> cart. Navigation is a typed state stack ([ADR-0013](../../docs/adr/0013-native-in-app-navigation.md)); Android hardware back pops it.

Stable `testID`s (iOS accessibility id, Android resource id) are listed in [the OpenSpec design](../../openspec/changes/native-shopping/design.md). Never rename or remove one without a versioned contract change.

## iOS simulator build and smoke test (macOS, full Xcode, CocoaPods)

`ios/` and `android/` are generated by prebuild and are not committed.

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
cd apps/mobile
CI=1 ../../node_modules/.bin/expo prebuild --platform ios --no-install
(cd ios && pod install)
xcodebuild -workspace ios/Tazumo.xcworkspace -scheme Tazumo -configuration Release \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/tazumo-dd CODE_SIGNING_ALLOWED=NO build
UDID=$(xcrun simctl create tazumo-local com.apple.CoreSimulator.SimDeviceType.iPhone-17 com.apple.CoreSimulator.SimRuntime.iOS-26-5)
xcrun simctl boot "$UDID"
xcrun simctl install "$UDID" /tmp/tazumo-dd/Build/Products/Release-iphonesimulator/Tazumo.app
xcrun simctl launch "$UDID" io.wopee.demos.tazumo
```

The Release configuration embeds the JS bundle, so no Metro server is needed. With Xcode 27 the `fmt` pod (11.0.2, pulled in by React Native 0.79) fails with `call to consteval function ... is not a constant expression`. Locally, add this at the top of the generated Podfile's `post_install` block and rerun `pod install`, until the Expo SDK upgrade in [#14](https://github.com/wopee-io-demos/tazumo/issues/14):

```ruby
installer.pods_project.targets.each do |t|
  next unless t.name == 'fmt'
  t.build_configurations.each { |c| c.build_settings['CLANG_CXX_LANGUAGE_STANDARD'] = 'c++17' }
end
```

If the Hermes download stalls during `pod install`, download `react-native-artifacts-0.79.2-hermes-ios-release.tar.gz` from Maven Central and set `HERMES_ENGINE_TARBALL_PATH` to the local file. Drive the simulator with [mobilecli](https://github.com/mobile-next/mobilecli) (`npx --yes mobilecli@1.0.24 agent install --device "$UDID"` once, then `dump ui`, `io tap x,y`, `screenshot`). Smoke path: open a product -> Add to cart -> cart icon -> increase/decrease/remove -> checkout stays disabled. Delete the simulator (`xcrun simctl delete "$UDID"`) and the DerivedData folder afterwards.

## Android emulator smoke (CI)

The `Android emulator smoke` job in `native-builds.yml` builds a release-variant x86_64 APK (debug keystore, JavaScript embedded), boots an API 34 emulator and runs [`tests/android-smoke.case.json`](tests/android-smoke.case.json) with Appium UiAutomator2 ([ADR-0010](../../docs/adr/0010-test-pyramid-native-automation.md)). Steps address elements by `sut-` IDs with the Android `id` strategy. React Native exposes `testID` as a bare resource-id (`sut-…`, no `io.wopee.demos.tazumo:id/` prefix), so the runner sets the UiAutomator2 setting `disableIdLocatorAutocompletion: true` after creating the session. Other Appium clients need the same setting, for example the capability `appium:settings[disableIdLocatorAutocompletion]: true`. The text and enabled-state checks use XPath on `@resource-id`. `tests/run-case.mjs` mirrors the report shape and step semantics of mobile-agent's `native.py` (private repo, so it is not fetched in this public CI). A negative case with a missing ID must fail on its last step. Screenshots, UiAutomator XML per step, `report.json`, the Appium log and the APK are uploaded as the `tazumo-android-smoke` artifact.

To run the same case against a local emulator with Appium running on port 4723:

```sh
adb install -r app-release.apk
node apps/mobile/tests/run-case.mjs apps/mobile/tests/android-smoke.case.json /tmp/tazumo-smoke
```

## CI builds

[`.github/workflows/native-builds.yml`](../../.github/workflows/native-builds.yml) runs the mobile unit tests, then produces an unsigned Android debug APK (`tazumo-android-debug-apk`) and an unsigned iOS Simulator `.app` (`tazumo-ios-simulator-app`). Artifacts are kept for 7 days. These are development builds, not store builds.

## EAS credentials and delivery process

Not configured yet: there is no Expo project ID and no `eas.json`. Store publication waits for name and trademark clearance ([#6](https://github.com/wopee-io-demos/tazumo/issues/6), [#10](https://github.com/wopee-io-demos/tazumo/issues/10)).

### Accounts (owned by the organization, not by an individual)

- Expo organization for `wopee-io-demos`, with a robot user whose access token is stored as the GitHub Actions secret `EXPO_TOKEN`.
- Apple Developer Program team with an App Store Connect API key (Issuer ID, Key ID, `.p8`) uploaded to EAS.
- Google Play Console developer account with a service account that has release rights for `io.wopee.demos.tazumo`; its JSON key is uploaded to EAS.

### Credentials

- Use EAS-managed credentials: `eas credentials` generates and stores the iOS distribution certificate, provisioning profiles and the Android upload keystore on Expo servers.
- Never commit `.p8`, `.p12`, `.mobileprovision`, `.jks`/`.keystore`, Play service-account JSON, `credentials.json` or `.env` files. Keep a backup of the Android keystore in the organization password manager, because losing it blocks Play updates.
- Rotate `EXPO_TOKEN` and the App Store Connect key when a maintainer leaves.

### Setup (one time)

```sh
npx eas-cli login
cd apps/mobile
npx eas-cli init            # writes the projectId into app.json
npx eas-cli build:configure # writes eas.json
npx eas-cli credentials     # per platform
```

Suggested `eas.json` profiles:

```json
{
  "build": {
    "development": {"developmentClient": true, "distribution": "internal", "ios": {"simulator": true}},
    "preview": {"distribution": "internal", "android": {"buildType": "apk"}},
    "production": {"autoIncrement": true}
  },
  "submit": {"production": {}}
}
```

### Delivery

1. `preview` builds for internal testers: `eas build --profile preview --platform all`. Android installs from the APK link; iOS uses ad hoc devices registered with `eas device:create`.
2. `production` builds: `eas build --profile production --platform all`, then `eas submit --platform ios` (TestFlight) and `eas submit --platform android` (Play internal testing track).
3. Promote from TestFlight and the internal track to wider tracks only after accessibility, language and smoke checks pass, and only once the name is cleared.
4. In CI, run EAS jobs only on `main` or `workflow_dispatch` with `EXPO_TOKEN`; never expose it to pull requests from forks.
