# Design

- **Pure and dependency-free.** The runtime has no dependencies, so `apps/api`, `apps/web` and `apps/mobile` can all import it. `@tazumo/core` and `@tazumo/commerce` are dev dependencies only. The fixture test uses core to check that product IDs and base prices exist, and the contract test uses commerce. Synthetic fixtures are exported only from the `@tazumo/product-options/fixtures` subpath, so a server can't pick up the demo menu by importing the main entry.
- **Money shape.** `priceSelection` takes the base price as `{ currency, minorUnits }` and returns `unitPrice` and `lineTotal` in the same shape. This matches `Money` in `@tazumo/commerce` (#80, merged) and the OpenAPI `Money` schema, so commerce takes `unitPrice` as an order line's unit price without conversion. `commerce-contract.test.ts` checks this at compile time with assignments in both directions. At run time it feeds every fixture's `unitPrice` and quantity through commerce `priceBreakdown` and asserts the same unit price and line total. Taking a `Money` instead of a bare number is what makes a currency mismatch detectable.
- **Integer arithmetic.** Deltas and base prices must be safe integers. Sums and the line total use `BigInt` and are checked against `Number.MAX_SAFE_INTEGER`, so an overflow is an error, never a rounded number. Quantity is capped at `MAX_LINE_QUANTITY` (999). The contract test asserts that this equals the commerce constant, so a line that prices here can't be rejected at the quote.
- **Availability.** `Option.available` is a boolean that the caller works out for each quote, for example from the `@tazumo/merchant-ops` `Availability` union through `isAvailableAt` (PR #76). Slice 2 storage must not persist it as a static column. Scheduling is not duplicated here. An unavailable default is skipped, so an optional group resolves to none and the line key changes with it. An unavailable explicit choice is rejected.
- **Defaults.** A group left out of the selection takes its available defaults. A group listed with an empty array is an explicit "none", which a required group rejects as too few.
- **Consistency rules.** `required` must equal `min >= 1`. A `single` group has `max` 1. `max` cannot exceed the option count. If a group marks any defaults, it marks at least `min` of them. Option IDs are unique across the whole product, so "an option from another group" is unambiguous.
- **Errors.** Every error has a code and a path, given as an array of segments, for example `['groups', 0, 'options', 1, 'priceDeltaMinor']` or `['selection', 'extras', 2]`.
  - Each stage collects all of its errors in one pass.
  - A failure carries `stage: 'definition' | 'selection' | 'pricing'`. In slice 2 the API can then map a catalogue fault to a server error and bad input to a client error.
  - A definition error stops the selection checks, and a selection error stops pricing.
  - A group list longer than the group's options gives one `too_many_options` error, not one error per item.
  - Messages never echo IDs that are long or malformed.
- **Line keys.** `lineKey` sorts group IDs and option IDs and serialises the result as JSON. It is therefore order-independent and can't collide on delimiter characters. Call it with the resolved selection that `validateSelection` and `priceSelection` return, which lists every group. Clients in slice 3 key cart lines by that result and never by the raw selection, so they agree with the server.
- **No ADR in slice 1.** No contract, storage or security trade-off arises in the package itself.

## Slice 2: contract, storage and quote

- **Storage** (ADR-0022): two tables, `product_option_groups` and `product_options`, keyed by product. The database repeats the cheap consistency rules (ID pattern, `min <= max`, `required = min >= 1`, `single` means `max = 1`, option IDs unique per product, an option's group belongs to the same product). The rest stays in `validateOptionGroups`, which the seed runs before inserting and the quote runs on every request.
- **Availability** is stored as the `@tazumo/merchant-ops` `Availability` JSON and resolved with `isAvailableAt` when a response is built, not as a static boolean. An invalid value resolves to unavailable.
- **Contract**: `Product.optionGroups` uses the package shape (`priceDeltaMinor` as a signed integer in the product price currency, `labelKey` for client translation), so clients can feed it to `priceSelection` unchanged. `OrderItem.selectedOptions` and `QuoteLine.selectedOptions` share the `OptionSelection` schema.
- **Quote**: each item is priced with `priceSelection` before commerce runs; commerce lines are keyed by `lineKey(productId, resolvedSelection)`, so commerce detects a duplicate configuration and two configurations of one product coexist. `selection` errors are client errors (400, or 409 when the only problem is availability, which can change while a client holds a cart); `definition` and `pricing` errors come from server data and are 500s that log only the stage and codes.
- **Snapshot**: `Quote.lines` returns what an order line has to keep. Storing it waits for #83 (ADR-0022).


## Slice 3a: web picker and cart lines

- **Cart key.** `Cart` stays `Record<string, number>`. `cartKey` returns the product ID for the product's default configuration (and for a product without options) and `lineKey` of the resolved selection otherwise. Every existing product-keyed cart, add button and the native app keep working, and two configurations of one product are separate lines. `priceCartLines` reprices every key on each render through `priceSelection` and drops malformed, non-canonical or no longer valid keys, so a stale or tampered key is never priced.
- **Test IDs.** `lineTestKey` gives a readable, `sut-*`-safe line ID: the product ID for the default configuration, otherwise the product ID followed by the chosen option IDs in definition order (`none` for an empty selection). A test enumerates every valid fixture configuration and asserts the IDs are unique. The existing `{productId}` cart IDs therefore still address the default configuration, and the detail-page IDs address the configuration currently selected, so no ID is renamed (SUT contract 0.6.0, minor).
- **Labels.** Synthetic option labels for the fixture label keys live next to the fixtures (`syntheticOptionLabel`), so web and native share them; a test asserts every key has a label in en, cs and de.
- **Accessibility.** Each group is a `fieldset` with a `legend`; single choice uses radios (with a "None" radio for an optional group), multiple choice uses checkboxes with a "Choose up to N" hint. Price deltas are part of the label text, unavailable options are disabled and say so, the unit price is a polite live region, and an invalid selection shows a `role="alert"` message and disables Add rather than blocking input.
